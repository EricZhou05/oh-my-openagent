## 人类干预是失败的信号

**人机协同（HUMAN IN THE LOOP）= 瓶颈**

以自动驾驶为例。当人类不得不接管方向盘时，这绝不是什么新功能，而是系统的失败。汽车本身无法自行应对当前状况。

**编写代码又有什么不同？**

当你发现自己不得不：
- 修复 AI 写了一半的代码
- 手动纠正明显的错误
- 一步步引导智能体完成任务
- 反复澄清相同的需求

这根本不是“人机协作”，而是 AI 没能做好自己的工作。

**Oh My OpenAgent 正是基于这一前提构建的**：智能体工作期间的人类干预从根本上说是一个错误的信号。如果系统设计得当，智能体应该独立完成工作，而不需要你像看护婴儿一样守着它。

---

## 无法区分的代码

**目标：智能体编写的代码应该与资深工程师编写的代码无法区分。**

不是“需要清理的 AI 生成代码”，也不是“一个不错的起点”，而是真正最终的、生产就绪的代码。

这意味着：
- 完全遵循现有的代码库模式
- 无需提示即可进行妥善的错误处理
- 编写真正测试到关键点的测试用例
- 拒绝 AI 废话（过度设计、不必要的抽象、范围蔓延）
- 仅在能带来价值时才添加注释

如果你能一眼看出某个提交是由人类还是智能体完成的，那么智能体就已经失败了。

---

## Token 成本与生产力

**如果能显著提升生产力，使用更多的 Token 是完全可以接受的。**

消耗更多 Token 来实现以下目标：
- 让多个专业智能体并行开展研究
- 无需人类干预即可彻底完成工作
- 在完成前对工作进行全面验证
- 跨任务积累知识

当这意味着 10 倍、20 倍甚至 100 倍的生产力提升时，这就是一项非常值得的投资。

**然而：**

我们并不追求无谓的 Token 浪费。系统针对以下方面进行了优化：
- 针对简单任务使用更便宜的模型（Haiku、Flash）
- 避免重复的探索工作
- 跨会话缓存学习成果
- 在收集到足够的上下文后立即停止研究

Token 效率固然重要，但绝不能以牺牲工作质量或增加人类认知负担为代价。

## 最小化人类认知负担

**人类只需要表达自己的诉求，其余的一切都是智能体的工作。**

有两种方法可以实现这一点：

### 方法 1：Prometheus（访谈模式）

你说：“我想添加身份验证。”

Prometheus 会：
- 研究你的代码库以理解现有的模式
- 根据实际发现提出澄清性问题
- 找出你未曾考虑过的边缘情况
- 在你做出决定时记录这些决策
- 生成一份完整的工作计划

**你提供意图，智能体提供结构。**

### 方法 2：Ultrawork（直接动手模式）

你说：“ulw add authentication”

智能体会：
- 找出正确的方法
- 研究最佳实践
- 遵循规范进行实现
- 验证一切正常运行
- 持续工作直至全部完成

**你提供意图，智能体搞定一切。**

在这两种情况下，人类的工作都是**表达自己的诉求**，而不是去管理具体如何实现。

## 可预测、连续、可委派

**理想的智能体应该像编译器一样工作**：输入 Markdown 文档，输出可以正常运行的代码。

### 可预测

在输入相同的情况下：
- 相同的代码库模式
- 相同的需求
- 相同的约束条件

输出应当保持一致。不应当是随机的、令人惊讶的，或者在你没有要求的地方展现出“创造力”。

### 连续

工作应当在中断后得以延续：
- 会话崩溃？使用 `/start-work` 恢复
- 需要暂时离开？进度会被持续追踪
- 跨越数天的项目？上下文会得到妥善保存

智能体会维护状态，你无需操心。

### 可委派

就像你可以把任务分配给一位得力的团队成员并信任他们能处理好一样，你也应该能够将任务委派给智能体。

这意味着：
- 拥有清晰且经过独立验证的验收标准
- 在出现问题时具备自我纠错行为
- 仅在真正需要时才向上升级（向 Oracle 或用户求助）
- 交付完整的工作，而不是“基本完成”的工作

## 核心循环

```
人类意图 → 智能体执行 → 验证后的结果
   ↑                       ↓
   └──────── 最小化 ────────┘
       （仅在真正失败时进行干预）
```

Oh My OpenAgent 中的一切设计都是为了让这个循环高效运转：

| 特性 | 目的 |
|---------|---------|
| Prometheus | 通过智能访谈提取用户意图 |
| Metis | 在歧义演变成 Bug 之前将其捕获 |
| Momus | 在执行前验证计划是否完整 |
| Orchestrator | 协调工作，无需人类进行微观管理 |
| Todo Continuation | 强制完成任务，防止“我已经做完了”的谎言 |
| Category System | 自动路由至最佳模型，无需人类做决策 |
| Background Agents | 并行开展研究，不阻塞用户操作 |
| Wisdom Accumulation | 从工作中汲取经验，避免重复犯错 |

---

## 这在实践中意味着什么

**你应该能够：**

1. 描述你的诉求（高层级或细节描述均可，由你决定）
2. 在需要时让智能体对你进行访谈
3. 确认计划（或者直接让 ultrawork 来处理）
4. 转身离开
5. 回来时看到已完成、已验证且生产就绪的工作成果

**如果你无法做到这一点，说明系统还有需要改进的地方。**

## 我们正在构建的未来

在这样一个世界里：
- 人类开发者专注于构建**什么**，而不是**如何**让 AI 去构建它
- 代码质量与编写者（无论是人还是机器）无关
- 复杂的项目变得和简单的项目一样轻松（只是耗时更长）
- “提示词工程”变得像“编译器调试”一样过时

**智能体应当是无形的。** 这并非指它被隐藏起来，而是指它能够自然地运转。就像电、自来水和互联网一样。

你按下开关，灯就会亮起，你不需要去思考电网是如何运作的。

这就是我们的目标。
